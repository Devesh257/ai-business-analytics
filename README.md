# AI Business Analytics Platform — Signal Ledger

A production-deployed AI-powered business analytics platform that transforms structured datasets into verified statistical insights, visualizations, and grounded business explanations.

The platform is designed around one core principle:

> **The LLM is never the source of numerical truth.**

All numerical analysis is performed deterministically using Python-based statistical methods. Large Language Models are used only to explain already-verified analytical evidence.

## Project Overview

Signal Ledger is an end-to-end analytics platform designed to reduce repetitive manual analysis while maintaining statistical reliability and traceability.

Users can:

- create authenticated accounts,
- upload structured business datasets,
- validate dataset quality,
- detect potential PII,
- automatically profile data,
- identify column semantics,
- generate an analysis plan,
- perform deterministic statistical analysis,
- discover and verify analytical insights,
- generate grounded AI explanations,
- review analysis history,
- compare previous runs,
- and export results.

The platform has been validated on datasets containing **100K+ rows**.

## Key Features

### Automated Dataset Profiling

The platform automatically inspects uploaded datasets and identifies:

- row and column counts,
- data types,
- missing values,
- numeric distributions,
- categorical fields,
- potential time-series fields,
- and useful analytical dimensions.

### Deterministic Statistical Analysis

Business insights are calculated using Python-based analytical methods rather than generated by an LLM.

Supported analytics include:

- descriptive statistics,
- IQR-based outlier detection,
- group comparisons,
- one-way ANOVA,
- Pearson correlation,
- time-series ordering,
- and trend analysis.

This ensures that analytical values remain reproducible and verifiable.

---

### Grounded LLM Explanations

The platform uses verified analytical evidence as the only context provided to the LLM.

The workflow is:

```text
Dataset
  ↓
Validation
  ↓
PII Detection
  ↓
Profiling
  ↓
Semantic Detection
  ↓
Analysis Planning
  ↓
Deterministic Analytics
  ↓

  ↓

  ↓

  ↓

  ↓

  ↓

```

The LLM does not calculate statistics and does not receive raw datasets.

## AI Reliability Architecture

The platform separates analytical computation from natural-language generation.

```text
Python determines the facts.
AI helps communicate them.
```

Before an insight can reach the LLM, it must pass deterministic verification.

Only controlled evidence is provided to the model, including:

- insight type,
- title,
- source columns,
- analytical method,
- verified evidence,
- verification results,
- and known limitations.

The following information is intentionally excluded from the LLM boundary:

- raw dataset rows,
- PII,
- unrestricted calculations,
- internal confidence metadata,
- internal lineage metadata,
- and unverified recommendations.

---

## Numeric Guardrails

LLM-generated explanations pass through a numeric guardrail before they are presented to the user.

The guardrail helps prevent:

- invented statistics,
- modified values,
- unsupported percentages,
- incorrect correlations,
- or numerical claims not present in the verified evidence.

If an AI explanation cannot be safely produced, the platform falls back to a deterministic explanation.

---

## Example Insight

A verified correlation insight may contain:

```text
Correlation: 0.9063
Observations: 10
p-value: 0.0003
```

The statistical engine produces and verifies these numbers.

The LLM may explain what the relationship means in business language, but it cannot replace or redefine the verified numerical evidence.

---

## PII Detection and Privacy Controls

Datasets are scanned for potential personally identifiable information before analysis.

The platform includes controls for identifying and protecting sensitive fields.

Raw datasets and detected PII are not sent to external LLM providers.

---

## Insight Verification

Each analytical insight follows a structured contract containing:

```python
class InsightContract(BaseModel):
    insight_type: str
    title: str
    source_columns: list[str]
    method: str
    evidence: dict[str, Any]
    calculation: dict[str, Any]
    verification: dict[str, Any]
    confidence: dict[str, Any]
    limitations: list[str]
```

This structure keeps calculations, evidence, verification, confidence, and limitations explicitly separated.

```env

```

- cost,
- latency,
- and the number of automatically generated explanations.

The application can still produce deterministic fallback explanations when AI generation is unavailable or disabled.

## Persistent Dataset Storage

Uploaded datasets are stored using a portable storage abstraction.

Production currently uses Railway persistent storage mounted at:

```text
/data
```

The storage layer supports portable object references rather than tightly coupling application logic to absolute filesystem paths.

This makes future migration to object storage such as S3 possible without redesigning the analytics pipeline.

## Engineering Principles

### 1. Deterministic Numerical Truth

Statistics are calculated by analytical code, not generated by language models.

---

### 2. Evidence Before Explanation

An insight must be analytically verified before it can be explained by AI.

---

### 3. Raw Data Stays Outside the LLM Boundary

External models receive controlled analytical evidence rather than complete datasets.

---

### 4. Graceful AI Failure

If an LLM is unavailable, misconfigured, or rejected by a guardrail, the analytical system continues to work using deterministic explanations.

---

### 5. Traceability

Dataset versions, analysis runs, verification information, and analytical history remain available for review.

---

### 6. Provider Independence

The LLM layer is abstracted from the analytics engine so model providers can change without redesigning statistical computation.
